# 장비관리대장 생성기 v2 — 부품설계도

> 목적: 고칠 곳을 빨리 찾게 하는 지도. "무엇을 바꾸려면 어느 파일 하나만 고치면 되는가"를 적는다.

## 1. 전체 흐름

```
[엑셀 통합본 .xlsx] ─┐
                     ├─► S2 엑셀 읽기 ──► 장비 레코드[] ──┬─► S4 Word 조립 ──► 시험장비관리대장.docx
[사진 폴더] ─► G2 사진 찾기 ─► G1 사진 변환 ─┘            │      ▲ S3 글자 맞춤
                                                         │
                                                         └─► G3 카탈로그 묶기 ─► 장비카탈로그.html
                                                                (레코드+사진+원본 엑셀+양식을 EQ_DATA 로)
                                                                         │
                                         카탈로그 안: C1 저장소 → C2 필터 → C3 결과 → C4 상세
                                                      C5 상세검색 · C6 엑셀 원본 보기 · C7 보내기(S4·S5 재사용)
```

- **배포물은 HTML 2개**: `장비관리대장_생성기.html`(만드는 도구), `장비카탈로그_날짜.html`(결과물·배포용)
- **소스는 부품 파일로 나뉘어 있고**, `python build.py` 가 합쳐서 배포용 HTML을 만든다.
- **Python 판**(`python/`)은 같은 설정(config.json)·같은 카탈로그 틀을 써서 같은 결과를 낸다.

## 2. 폴더 구조

```
eqledger/
├─ build.py                    # 부품 합치기 → dist/
├─ assets/ledger.docx          # Word 양식 (이 파일을 바꾸면 양식이 바뀜, 표 구조는 유지)

├─ shared/                     # 생성기·카탈로그가 함께 쓰는 부품

│  └─ js/ 00_core · 10_format · 20_excel_reader · 30_text_fit · 40_docx_builder · 50_xlsx_writer
├─ generator/                  # 생성기 화면
│  ├─ index.html · generator.css
│  └─ js/ 10_image_convert · 20_image_match · 30_catalog_pack · 90_app
├─ catalog/                    # 카탈로그 화면
│  ├─ index.html · catalog.css
│  └─ js/ 10_store · 20_filters · 30_results · 40_detail · 50_filter_panel · 60_sheets · 70_actions · 90_main
├─ python/                     # Python 판 (창 + 명령행)
│  ├─ 장비관리대장_생성기.py   # 실행 파일
│  └─ eqledger/ config · util · excel_reader · text_fit · docx_builder · images · catalog · generate · gui · cli
│     └─ assets/               # build.py 가 복사: config.json, ledger.docx, catalog_template.html
├─ tests/                      # 끝-끝 시험(Playwright), JS↔Python 글자맞춤 일치 시험
├─ docs/                       # 이 문서, 매뉴얼, 변경이력
└─ dist/                       # 빌드 결과 (배포용)
```

| uid | — | `시트#행` (고유) |

### 4-2. 카탈로그 데이터 `EQ_DATA` (G3/catalog.py 출력 → 카탈로그 입력)
```js
{ schema: 2, generated: "2026.11.23 10:43",
  source: { name, size, b64 },          // 원본 엑셀 통째로 (내려받기·공유)
  sheetsView: [{ name, header:[..], idCol, rows:[[엑셀행, 칸...]] }],   // 엑셀 원본 보기
  records: [레코드 + ph(사진 키)],
  images: { i0: "data:image/jpeg;base64,..." },   // 같은 사진은 한 번만
  template: "ledger.docx base64" }      // 카탈로그 안에서 Word 만들기
```

## 5. 한 쪽 유지 규칙 (Word)
- 양식의 ‘주요 성능 및 특징’ 행은 높이가 ‘최소’ 지정이라 글이 길면 행이 늘어나 쪽이 넘어갔다.
- v2: S3 가 칸 너비로 줄 수를 계산해 **10pt → 최소 5.5pt** 사이에서 들어가는 가장 큰 크기를 고르고, **줄 간격을 ‘고정(크기×1.2)’** 으로 지정한다. 줄 높이가 글꼴과 무관해져 경기천년바탕이 없는 PC 에서도 계산이 맞는다.
- 규격·제조사·도입처 등 3행 병합 칸도 같은 방식(최소 6pt). 구성내역이 5행을 넘으면 행 높이를 나누고 ‘고정’으로.
- 최소 크기로도 넘칠 때는 실행 기록에 `넘칠 수 있음` 경고, 생성기 표 ‘성능 글자’ 열에 `넘침 위험` 표시.

## 6. 자주 바꾸는 것 → 고칠 곳

| 바꾸고 싶은 것 | 고칠 곳 |
|---|---|
| 엑셀 열 이름이 바뀜 | `shared/config.json` → columns 의 aliases 에 새 이름 추가 |
| 장비구성 시트 열 이름 | `config.json` → componentColumns |
| 기본으로 선택할 시트 / 제외할 시트 | `config.json` → sheets.defaultOn / sheets.exclude |
| 금액 구간 칩 | `config.json` → priceBuckets |
| 글자 최소 크기·줄 간격 | `config.json` → form.note.min, form.lineFactor |
| 사진 압축 기준 | `config.json` → image |
| Word 양식 디자인 | `assets/ledger.docx` (표 구조 유지) → 칸 크기가 바뀌면 config.form 도 수정 |
| 카탈로그 색·모서리·간격 | `catalog/catalog.css` 맨 위 :root 변수 |
| 카탈로그 상세 화면 항목 | `catalog/js/40_detail.js` html() |
| 카탈로그 내보내기 열 | `catalog/js/70_actions.js` filteredXlsx() |

고친 뒤 `python build.py` → `dist/` 의 HTML 배포. (Python 판은 assets 가 자동 갱신됨)

## 7. 시험
```bash
python build.py
python tests/test_fit_parity.py 통합.xlsx                      # JS·Python 글자맞춤 결과 일치
python tests/e2e_generator.py 통합.xlsx 사진폴더 출력폴더       # 생성기 끝-끝 (Playwright)
python tests/e2e_catalog.py 출력폴더/장비카탈로그_*.html 출력폴더  # 카탈로그 기능
soffice --headless --convert-to pdf 출력폴더/시험장비관리대장_*.docx   # 쪽 수 = 장비 수 × 2 확인
```
